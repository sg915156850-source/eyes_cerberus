# Цель проекта: Eyes Cerberus

Документ написан для чтения ИИ-агентом. Он задаёт целевое состояние проекта
и правила приоритизации. Он не описывает текущее состояние.

## Статус документа

- Тип: целевое состояние (target state), сформулировано владельцем 22.09.2026.
- Цель шире текущей реализации: сейчас это демон защиты одного хоста
  (v2.1), а цель — система защиты удалённых серверов с удалённым управлением.
  Разрыв описан ниже, он и есть содержание работы.

## Цель одной строкой

Полноценная защитная система для удалённых серверов: мониторинг состояния
безопасности и удалённое управление ею.

## Целевое состояние

Цель достигнута, когда одновременно выполнены все пункты:

1. Система ставится на несколько удалённых серверов и обслуживает их как
   парк, а не как отдельные не связанные установки.
2. Мониторинг: состояние защиты каждого сервера видно из одной точки, включая
   сработки, версию сигнатур и факт того, что демон жив.
3. Удалённое управление: с управляющей стороны можно менять политику,
   обновлять сигнатуры и реагировать на инцидент, не заходя на каждый сервер
   руками.
4. Канал управления аутентифицирован в обе стороны, и компрометация
   управляющей стороны не даёт автоматически root на всём парке.
5. Сохранено свойство v2.1: высокоуверенные сигнатуры срабатывают
   автоматически, эвристики только предупреждают.

## Измеримые критерии

| Показатель | Целевое значение | Источник |
|---|---|---|
| Серверов под управлением из одной точки | > 1 | прогон на парке |
| Видимость статуса демона | по каждому хосту, в реальном времени | панель мониторинга |
| Обновление сигнатур на парке | одной операцией | `update-sigs` |
| Ложные срабатывания на легитимных процессах | 0 | тесты в CI |
| Тесты в CI | проходят на Debian 12, Ubuntu 24.04, AlmaLinux 9 | CI |

## Что вне цели

- Превращение в антивирус или EDR. Проект — узкая проверяемая подстраховка
  со смещением в сторону «не трогать легитимный процесс», и это свойство
  сохраняется при расширении на парк.
- Замена харденинга сервера.
- Автоматические действия по эвристикам. История v1 прямо показывает цену
  ошибки: эвристика по CPU убивала `unattended-upgrade`, `fwupd` и `pg_dump`.
  На парке из многих серверов такая ошибка масштабируется на все сразу.

## Как агенту использовать этот документ

- Главный риск перехода к удалённому управлению: агент на каждом хосте,
  принимающий команды извне, сам становится целью. Канал управления
  проектируется как часть модели угроз, а не как транспорт поверх готовой
  логики.
- Приоритет при конфликте: отсутствие ложных срабатываний выше полноты
  обнаружения. Система, останавливающая рабочие процессы, будет выключена
  владельцем, и тогда защиты не останется вовсе.
- Репозиторий публичный. Индикаторы компрометации конкретного хоста,
  внутренние адреса и всё, что помогает атакующему обойти детект именно на
  этих серверах, в него не попадает.
- `KNOWN_THREATS.md` и `etc/signatures/` — источник правды по детектам,
  `ROADMAP.md` — по очерёдности. Этот документ задаёт цель, они — способ.
