# Roadmap

Дата составления: 2026-09-06. Основано на аудите `cloud.md` (2026-09-04) и
разборе кода v2.0.

## Исходная позиция

Eyes Cerberus сейчас — рабочий инструмент для **одного конкретного хоста**,
написанный после реального инцидента (`/let` dropper + `nc :9009`, март–апрель
2026). Сигнатуры описывают этот инцидент: один MD5, два IP, шесть путей. На
чужой машине из коробки сработают только эвристики.

Ценность проекта — не в покрытии детекторов (Wazuh/CrowdSec/Falco покрывают
больше и бесплатны), а в трёх вещах:

1. **Ноль зависимостей и ноль инфраструктуры** — bash + coreutils + iptables,
   без manager/indexer/dashboard. Ставится за минуту, читается целиком.
2. **Аккуратная модель ответственности** — тиры HARD/SOFT, `chmod 000` вместо
   `rm`, поиск процессов через `/proc/*/exe`, а не `pgrep -f`, глобальный
   dry-run.
3. **Реальный кейс** — и разобранный инцидент, и разобранный провал v1
   (`Type=oneshot` + `nohup`, из-за чего защита молча не работала неделями).

Роадмап ниже сохраняет эти три вещи и снимает то, что мешает проекту быть
полезным кому-то, кроме автора.

## Принципы (чего не делаем)

- Не гонимся за паритетом фич с Wazuh/CrowdSec — это проигрышное поле и потеря
  единственного УТП.
- Не добавляем рантайм-зависимостей в агент. `python3`, `jq`, `curl` не должны
  быть обязательными для работы сенсорного цикла.
- Не удаляем файлы с диска в автоответе. `chmod 000` + карантинная копия —
  контракт, на котором строится доверие к авто-режиму.
- Не публикуем `curl | sudo bash` без проверки контрольной суммы.
- Не обещаем «защиту». Формулировка README («narrow, auditable safety net») —
  честная, держимся её.

# Фаза 0 — Гигиена

Мелкие вещи, которые делают репозиторий пригодным к показу кому-то ещё.

### 0.1 SECURITY.md — привести в соответствие с реальностью
Сейчас: `[YOUR_EMAIL_HERE]` вместо контакта, ссылка на несуществующий
`defense_config.cfg`, чеклист «перед публикацией» вместо политики.
**Готово когда:** указан рабочий канал раскрытия, все упомянутые файлы
существуют, описан scope (что считается уязвимостью в контексте host-агента
под root).

### 0.2 Изолировать `ir/honeypot.sh`
325 строк с явной пометкой «potentially mislead attackers». Активное
противодействие — отдельный юридический разговор, который не нужен ни при
показе репозитория, ни при продаже услуги.
**Готово когда:** файл вынесен в `ir/experimental/` с README о правовых
рисках, исключён из пакетов и релизов, README основного проекта на него не
ссылается как на штатный инструмент.

### 0.3 Зафиксировать lint-базу
**Готово когда:** `.shellcheckrc` в репозитории, `shellcheck -x -S warning`
проходит на всём дереве без ошибок (SC2034 для конфиг-переменных
библиотеки подавлен точечно, а не глобально).

# Фаза 1 — Мультихост и установка

Блокер №1 для всего остального: `WorkingDirectory=/root/projects/eyes_cerberus`
захардкожен в systemd-юните, состояние и конфиг лежат внутри клона репозитория.

### 1.1 Расхардкодить пути
**Готово когда:** `lib/common.sh` поддерживает два режима —
*repo-local* (разработка: конфиг и `state/` внутри клона, как сейчас) и
*FHS* (`/etc/eyes-cerberus`, `/var/lib/eyes-cerberus`, `/opt/eyes-cerberus`).
Режим выбирается автоматически по расположению кода и переопределяется
переменными `CERBERUS_CONF_DIR` / `CERBERUS_STATE_DIR`. Существующие
инсталляции из репозитория продолжают работать без изменений.

### 1.2 `install.sh` / `uninstall.sh`
**Готово когда:** установка на чистый Debian/Ubuntu/RHEL-хост одной командой,
идемпотентна, переносит существующий `state/` при апгрейде с repo-local,
`uninstall.sh` умеет `--purge` и по умолчанию сохраняет улики и карантин.

### 1.3 `Makefile`
**Готово когда:** `make lint test install uninstall deb` работают из чистого
клона.

### 1.4 Hardening systemd-юнита
Демон под root читает `/proc/*/environ` (там бывают секреты) и пишет улики —
он сам по себе мишень.
**Готово когда:** в юните нет захардкоженного пути, включены
`NoNewPrivileges`, `ProtectHome`, `ProtectSystem`, `PrivateTmp=no`
(нужен доступ к реальному `/tmp`), ограничен `CapabilityBoundingSet`
(`CAP_KILL`, `CAP_NET_ADMIN`, `CAP_NET_RAW`, `CAP_DAC_READ_SEARCH`,
`CAP_SYS_PTRACE`), настроен `OnFailure=` для алерта о падении.

### 1.5 Сборка `.deb`
**Готово когда:** `make deb` собирает устанавливаемый пакет без внешних
зависимостей кроме `dpkg-deb`, пакет ставит те же пути, что `install.sh`.

# Фаза 2 — Тесты и CI

История v1 — прямое доказательство, что регрессии здесь молчаливые: защита не
работает, а выглядит работающей.

### 2.1 Тестовая обвязка
**Готово когда:** тесты на `bats`, окружение подменяется PATH-шимами
(`ps`, `ss`, `iptables`, `systemctl`) и временным `CERBERUS_STATE_DIR`, ни один
тест не трогает реальный хост и не требует root.

### 2.2 Покрытие детекторов и ответчика
**Готово когда:** покрыты `read_sig`, JSON-эскейпинг событий,
`detect_malware_paths`, `detect_c2` (argv + сокеты), `detect_miner`
(HARD/SOFT-развилка), `baseline_diff`, `handle_finding` в dry-run и карантин с
восстановлением.

### 2.3 CI
**Готово когда:** GitHub Actions гоняет `shellcheck` + `bash -n` + `bats` на
push и PR, и отдельной job'ой — установку и smoke-тест в контейнерах
Debian 12, Ubuntu 24.04, Rocky 9.

# Фаза 3 — Надёжность

Дефекты, найденные при разборе кода. Каждый — с тестом.

### 3.1 Убрать `python3` из горячего пути
`emit_event()` вызывает `python3` на **каждое** событие для JSON-эскейпа;
python3 нигде не заявлен зависимостью, а sed-фолбэк не экранирует переводы
строк и управляющие символы — argv злоумышленника ломает JSONL.
**Готово когда:** эскейп сделан на чистом bash, покрыт тестом на кавычки,
бэкслеши, переводы строк и управляющие байты, `python3` больше не вызывается.

### 3.2 Ротация журналов
`state/events.jsonl` и `state/cerberus.log` растут без ограничений и однажды
забьют диск.
**Готово когда:** встроенная ротация по размеру с настраиваемым лимитом и
числом поколений, плюс конфиг для `logrotate` в пакете.

### 3.3 Восстановление из карантина
Автоответ без кнопки «откатить» — причина, по которой ставят
`AUTO_RESPONSE=0` и больше не возвращаются.
**Готово когда:** `master.sh quarantine list` показывает содержимое,
`master.sh restore <id>` возвращает файл на исходный путь с исходными правами,
пишет событие в журнал и требует подтверждения.

### 3.4 Счётчик CPU-эвристики
`state/cpu_sustain.tsv` ключуется по PID: переиспользование PID даёт ложный
счётчик, а флаг `emitted` не сбрасывается никогда.
**Готово когда:** ключ включает `starttime` процесса, записи исчезнувших
процессов вычищаются.

### 3.5 SHA-256 в сигнатурах
MD5-матчинг обходится изменением одного байта.
**Готово когда:** поддержан `etc/signatures/malware_sha256.txt` наравне с
`malware_md5.txt`, в событиях фиксируются оба хэша.

### 3.6 Проверка прав на конфиг и сигнатуры
`etc/cerberus.env` исполняется как bash от root — любой, кто может в него
дописать, получает RCE от root.
**Готово когда:** демон при старте отказывается работать, если конфиг или
каталог сигнатур доступны на запись не только root'у.

# Фаза 4 — Детекторы общего назначения

То, что превращает «ловит мой инцидент» в «ловит типовой компромет VPS».
Каждый детектор — SOFT (alert-only) по умолчанию, дешёвый по CPU, с флагом
включения.

### 4.1 Reverse shell по argv
`bash -i >& /dev/tcp/...`, `sh -i` с перенаправлением, `python -c` с сокетом,
`perl -e` с `Socket`.

### 4.2 Fileless / memfd
Процесс, исполняющийся из `memfd:` или `/dev/fd` — классика дропперов, которые
не оставляют файла на диске. Соседний случай к существующему `deleted_exe`.

### 4.3 Новые setuid/setgid-бинари
Появление setuid-файла вне списка, зафиксированного в baseline.

### 4.4 Расширение baseline
Добавить к снимку: `/etc/passwd`, `/etc/group`, `/etc/sudoers` и
`/etc/sudoers.d/`, `sshd_config`, PAM-конфигурацию.

### 4.5 Загрузчики в точках персистентности
Юнит или cron-задание, содержащие `curl|sh`, `wget|bash`, `base64 -d|sh`.

# Фаза 5 — Сигнатуры как обновляемый фид

Точка, где инструмент перестаёт быть «про один инцидент».

### 5.1 `cerberus.sh update-sigs`
**Готово когда:** команда тянет подписанный/проверяемый по SHA-256 архив
сигнатур с настраиваемого URL, атомарно подменяет `etc/signatures/`, умеет
`--dry-run` и откат, локальные добавления пользователя не затираются.

### 5.2 Наполнение фида
Отдельный репозиторий сигнатур, наполняемый из открытых источников
(abuse.ch ThreatFox/Feodo, списки майнинг-пулов). Вне кода этого репозитория.

# Фаза 7 — Монетизация (не код)

Порядок — по скорости получения первых денег, а не по амбициозности.

### 7.1 Услуга: разбор скомпрометированного VPS *(недели)*
`ir/` + пройденный на себе кейс = готовый пакет: аудит, чистка, постановка
мониторинга, отчёт (Фаза 6.1). Спрос стабильный и видимый (r/selfhosted,
хостинг-форумы, фриланс). Ориентир: разовая работа $150–400, далее
$30–100/сервер/мес за разбор алертов. Репозиторий здесь — доказательство
компетенции, а не товар. Вложения ≈ 0.

### 7.2 Контент как воронка *(параллельно, стоит 0)*
Два поста: разбор инцидента с `/let` и разбор провала v1 («моя защита молча не
работала три недели»). Второй честнее и заходит лучше. Конвертируется в 7.1.

### 7.3 Open-core: бесплатный агент + платная панель *(3–6 месяцев)*
`NOTIFY_METHOD=webhook` — уже готовый транспорт. Панель даёт то, чего агент
дать не может физически:
- агрегация с N хостов;
- **алерт «агент замолчал»** — локальный демон не может сообщить о собственной
  смерти, а первым делом атакующий с root убивает именно его;
- дедуп и подавление шума;
- хранение улик **вне** скомпрометированного хоста (сейчас `state/evidence`
  лежит на той же машине, которую взломали);
- удалённое пере-baseline и раскатка сигнатур.

Ориентир: $3–5/хост/мес. Дешёвая альтернатива SaaS — продавать self-hosted
панель по коммерческой лицензии: нет хостинга, нет ответственности за чужие
данные, нет GDPR, и для аудитории «у меня свой VPS, потому что я не доверяю
облакам» это убедительнее.

### 7.4 Дистрибуция через чужие площадки
1-click-приложения в маркетплейсах Hetzner/DigitalOcean/Vultr; интеграция с
Coolify, CapRover, Cloudron; расширение для Plesk/cPanel — единственный
сегмент, где за админ-плагины платят и где есть встроенный биллинг.

### 7.5 Чего не монетизировать
Платные сигнатуры (abuse.ch отдаёт бесплатно), «Enterprise EDR» (не выиграть у
CrowdSec на его поле), донаты как основной источник.

# Требует решения владельца

Эти вопросы нельзя закрыть кодом — они меняют стратегию:

1. **Лицензия.** Сейчас MIT. Для open-core (7.3) агент разумнее держать под
   AGPL, иначе любой поднимет вашу же панель как конкурирующий сервис. Сменить
   лицензию можно, только пока автор один — то есть **до** первого принятого
   PR.
2. **Судьба `ir/honeypot.sh`.** Фаза 0.2 переносит его в `ir/experimental/` и
   не удаляет. Решение «удалить совсем» или «оставить как есть» — за
   владельцем.
3. **SaaS или self-hosted панель** (7.3) — определяет, нужна ли вообще
   инфраструктура и юрлицо.
4. **Публиковать ли репозиторий.** Сейчас приватный. Услуга (7.1) работает и с
   приватным; open-core (7.3) требует публичного агента.
